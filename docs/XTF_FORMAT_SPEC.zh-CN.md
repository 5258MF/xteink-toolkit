# XTF 字体容器格式规范

版本 1.0 · 适用对象：XTEINK X3 固件 V6.4.x 读取的 `.xtf` 文件

[English](XTF_FORMAT_SPEC.md) | **简体中文**

---

## 1. 范围

本文规定 `.xtf` 字体容器的二进制布局。这是一个 2 bit 灰阶、可按码位随机寻址的字形存储，供 XTEINK X3 电子阅读器使用。

本文定义每个字段、它的合法取值，以及合规文件必须满足的约束。本文不规定字形轮廓如何光栅化。渲染器选用哪种抗锯齿方式只影响观感，不影响文件是否合规。

用途尚未确定的字段标为**不透明（opaque）**，并要求从已知可用的文件中原样复制。这类字段不是可选项。

---

## 2. 约定

- 所有多字节整数均为**小端序**。
- `u8`、`u16`、`u32`、`i16` 分别表示无符号 8/16/32 位整数与有符号 16 位整数。
- 偏移量均以文件起始位置为基准，单位为字节。
- “样本”指厂商自带工具链产出的 `.xtf` 文件。
- 关键词“必须”“不得”“应该”“可以”按 RFC 2119 的用法理解。

---

## 3. 文件布局

```
偏移                      长度          内容
0x0000                    64            文件头
0x0040                    16 × N        区间表
0x0040 + 16N              L             tail 表
...                       补齐          补零至 data_start
data_start                G × P         字形记录
```

| 符号 | 定义 |
|---|---|
| `N` | 区间表行数，取自文件头 `0x14` |
| `G` | 字形记录数，取自文件头 `0x18` |
| `L` | tail 表长度，取自文件头 `0x3c`（所有样本均为 95） |
| `P` | 每条字形记录的字节数，取自文件头 `0x28` |
| `data_start` | `(0x40 + 16N + L + 0x1FF) & ~0x1FF`，取自文件头 `0x24` |

文件长度必须等于 `data_start + G × P`。

`data_start` 按 512 字节对齐。所有样本都落在 `0x4600`，因为它们的 `N = 1093`、`L = 95` 相同。

## 4. 文件头

### 4.1 字段

偏移量为绝对偏移，长度为字节数。表中数值取自三份样本，以标称字号区分。

| 偏移 | 类型 | 40 号 | 43 号 | 46 号 | 含义 | 可否重算 |
|---|---|---|---|---|---|---|
| `0x00` | char[4] | `XTF0` | `XTF0` | `XTF0` | 魔数 | 常量 |
| `0x04` | u8 | 1 | 1 | 1 | 主版本 | 常量 |
| `0x05` | u8 | 5 | 5 | 5 | 次版本 | 常量 |
| `0x06` | u8 | 0x40 | 0x40 | 0x40 | **不透明** | 复制 |
| `0x07` | u8 | 2 | 2 | 2 | 每像素位数 | 常量 2 |
| `0x08` | u16 | 3 | 3 | 3 | **不透明** | 复制 |
| `0x0a` | u8 | 41 | 44 | 47 | 排版 em + 1 | `em_pitch + 1` |
| `0x0b` | u8 | 52 | 57 | 59 | 字格高 `gridH` | 见 §4.2 |
| `0x0c` | u8 | 40 | 43 | 46 | 渲染 em | 见 §4.2 |
| `0x0d` | u8 | 41 | 58 | 46 | **不透明** | 复制 |
| `0x0e` | u16 | 19 | 35 | 21 | **不透明** | 复制 |
| `0x10` | u16 | 40 | 43 | 45 | 默认步进 | 复制 |
| `0x12` | i16 | −12 | −14 | −14 | 下伸部 | 复制 |
| `0x14` | u32 | 1093 | 1093 | 1093 | 区间数 `N` | `len(table)/16` |
| `0x18` | u32 | 19909 | 19909 | 19909 | 字形数 `G` | `Σ count` |
| `0x1c` | u32 | 64 | 64 | 64 | 文件头长度 | 常量 64 |
| `0x20` | bytes[5] | 0 | 0 | 0 | 保留 | 置零 |
| `0x25` | u8 | 0x46 | — | 0x46 | **不透明** | 复制 |
| `0x26` | u16 | 0 | 0 | 0 | 保留 | 置零 |
| `0x28` | u16 | 574 | 629 | 710 | 每记录字节数 `P` | `1 + gridH × stride + 1` |
| `0x2a` | u16 | 0 | 0 | 0 | 保留 | 置零 |
| `0x2c` | u32 | 11427766 | 12522761 | 14135390 | 字形数据长度 | `G × P` |
| `0x30` | bytes[8] | 各样本不同 | 各样本不同 | 各样本不同 | **不透明**，疑似哈希 | 复制 |
| `0x38` | u32 | 0x4490 | 0x4490 | 0x4490 | tail 表偏移 | `0x40 + 16N` |
| `0x3c` | u32 | 95 | 95 | 95 | tail 表长度 `L` | 样本恒为 95 |

### 4.2 可重算的几何量

以下三个量由其他字段推导，与任何样本无关：

```
stride = ceil(0x0a × 2 / 8)        每行像素的字节数
cellW  = stride × 4                每个存储格的像素数
P      = 1 + gridH × stride + 1    每条字形记录的字节数
```

`gridH` 与渲染用 `em` 是两个独立输入。`gridH` 是行距，`em` 是绘制字号。渲染器可以用大于排版步距的 em 绘制，此时字面宽度超出步进，见 §8.3。

`0x0b` 与 `0x0c` 没有跨字号成立的公式。样本取值：`(40 号 → 52/40)`、`(43 号 → 57/43)`、`(46 号 → 59/46)`。任意组合下，`gridH` 按排版需要选定，渲染 em 写入实际使用的字号。这两个字段是读者端的输入，不是推导值。

### 4.3 不透明字段

`0x06`、`0x08`、`0x0d`、`0x0e`、`0x10`、`0x12`、`0x25` 与 `0x30..0x37` 的取值没有已知推导方式。样本之间的差异与任何几何参数都不相关：

| 字段 | 40 号 | 43 号 | 46 号 |
|---|---|---|---|
| `0x0d` | 41 | 58 | 46 |
| `0x0e` | 19 | 35 | 21 |
| `0x10` | 40 | 43 | 45 |

实现必须从厂商工具链产出的文件里复制这些字节。`0x30..0x37` 置零已知可用，其余字段没有这个保证。

## 5. 区间表

起始于 `0x40`，共 `N` 行，每行 16 字节。

```c
struct XtfInterval {
    uint32_t first;      // 本区间首个码位
    uint32_t count;      // 连续码位个数
    uint32_t cum_index;  // 之前所有 count 之和
    uint32_t count_x16;  // count << 16
};
```

四条约束，所有样本均满足：

1. 各行必须按 `first` 升序排列，且区间不得重叠。
2. `cum_index[i]` 必须等于 `Σ count[0..i-1]`。
3. `cum_index[N-1] + count[N-1]` 必须等于文件头 `0x18` 处的字形总数。
4. `count_x16` 必须等于 `count << 16`。

区间表描述的是字符集，与字形几何无关。字符集相同的样本共用同一张表。码位到记录下标的换算：

```
index(cp) = cum_index[i] + (cp - first[i])   条件 first[i] ≤ cp < first[i] + count[i]
```

码位不在表内表示字体不含该字，必须交由读者端的回退机制处理。

记录位置为 `data_start + index × P`。

## 6. tail 表

存放于 `toc_end = 0x38` 处，长度为 `0x3c`，所有样本均为 95 字节。它不是零填充，读者会解析它。

内容为 95 个 8 到 34 之间的字节，取值随 `gridH` 缩放：

| 样本 | `gridH` | 字节之和 | 最小 | 最大 |
|---|---|---|---|---|
| 40 号 | 52 | 1782 | 8 | 30 |
| 46 号 | 59 | 2022 | 9 | 34 |

`2022 / 1782 = 1.135`，`59 / 52 = 1.135`，两者相同。缩放与 `gridH` 成正比，但逐项不可插值，从一个 `gridH` 换算到另一个不是逐字节乘固定系数。

要求：实现必须从样本原样复制这 95 字节。`gridH` 不匹配会改变读者端的行布局。只有在找不到完全匹配时，才允许改用邻近 `gridH` 的表。

两份已知表见附录 B。

## 7. 字形记录

### 7.1 结构

从 `data_start` 开始，共 `G` 条记录，每条 `P` 字节，按 `cum_index` 顺序排列。单条结构：

```c
struct XtfGlyph {
    uint8_t  advance;              // 1 字节，不参与排版，见 §8.1
    uint8_t  bitmap[gridH × stride];
    uint8_t  terminator;           // 1 字节，恒为 0x00
};
```

`P = 2 + gridH × stride`。

`advance` 逐字存储，但不影响排版。样本写入的是与文件头 `0x10` 相同的常量，实现应该照此处理。

`terminator` 必须为 `0x00`。

### 7.2 像素编码

每个字节存放四个水平相邻像素，高位在前：

```
pixel[4b + k] = (byte >> (6 - 2k)) & 0b11      k = 0..3
```

行自上而下存储，每行 `stride` 字节。`cellW = stride × 4` 之后的列不使用。当 `cellW` 为 48、`em_pitch` 为 44 时，第 44 到 47 列位于步进之外，必须置零，见 §8.3。

等级语义：

| 等级 | 含义 |
|---|---|
| 0 | 纸白，无墨 |
| 1 | 浅 |
| 2 | 深 |
| 3 | 满墨 |

### 7.3 排布

位图在 `gridH × cellW` 格内的位置由写入方决定。影响观感的有两点：

1. **纵向居中。** 墨迹外接框应该在 `gridH` 内居中，不要按字体上伸部与下伸部定位。字体度量因字体而异，按度量定位会出现可见的基线偏移。
2. **横向原点。** 墨迹应该从第 0 列开始，除非要刻意复刻某个左边距。用少量测试字推导出的左边距不可靠：28 个字的测试集可能报最左墨迹在第 3 列，而「钧」这类字从第 0 列起笔，从第 3 列裁切会把偏旁的第一笔切掉。

## 8. 排版模型

### 8.1 步进与步距

读者按 `advance_pitch = 0x0a - 1` 像素逐字推进。文件头 `0x10` 处的步进值与每记录里的 `advance` 字节都不参与这个计算。

### 8.2 每行字数

在 528 像素面板上的实测结果：

| `0x0a` | `advance_pitch` | 每行字数 |
|---|---|---|
| 45 | 44 | 12 |
| 46 | 45 | **未实测** |
| 47 | 46 | 10 |

`chars ≈ 57 - 0x0a` 能同时拟合两个实测点，但这是经验式，不是推导结果。直接相除不成立：`528 / 44 = 12` 与第一点相符，而 `528 / 46 = 11.48` 得不到 10。

对于尚未实测的 `0x0a`，实现不得依赖计算得出的字数。

### 8.3 字面宽度预算

存储格宽 `cellW` 等于 `stride × 4`，通常大于 `advance_pitch`。字面宽于步距时会压到相邻字符。

```
步距                 44      由 0x0a = 45 得出
可用字面宽           43      步距减 1，留出 1 像素间隙
cellW                48      仅用于存储，不是排版量
```

渲染 em 产生的字面超过可用宽度时有两种处理方式，效果并不等价：

| 方式 | 笔画粗细 | 结果 |
|---|---|---|
| 重采样到目标宽度 | 按缩放比例变细 | 偏旁笔画变瘦 |
| 裁切到目标宽度 | 不变 | 右边缘被截断 |

裁切保持笔画粗细，应该优先采用。位于步距及其之后的列必须置零，否则多出的部分会叠加到下一个字形上。

## 9. 量化

读者每个像素存 2 bit，渲染方必须把 8 bit 覆盖率压到四级。厂商工具链使用的切点：

```
覆盖率 ≥ 64/255   判为等级 1
覆盖率 ≥ 128/255  判为等级 2
覆盖率 ≥ 192/255  判为等级 3
```

四级在面板上的实测相对反射率：

| 等级 | 相对反射率 |
|---|---|
| 0 | 1.000 |
| 1 | 0.578 |
| 2 | 0.132 |
| 3 | 0.000 |

等级 2 的亮度只有纸白的 13%。切点取 128/255 时，一个覆盖率 50% 的像素（几乎看不见的抗锯齿边缘）会被画成接近纯黑的等级。把切点提高到 `96/160/224` 可以减少零散的边缘像素，代价是笔画略微变细。实现可以将切点作为参数暴露。

## 10. 构造流程

合规的写入方按以下步骤产出文件。

```
1.  确定 em_render、em_pitch、gridH、face_width。
2.  stride   = ceil((em_pitch + 1) * 2 / 8)
    cellW    = stride * 4
    P        = 1 + gridH * stride + 1
3.  取得骨架：文件头、区间表、tail 表。
    校验 tail 表长度为 95，且 N 与表长度一致。
4.  data_start = (0x40 + 16N + L + 0x1FF) & ~0x1FF
5.  对区间表中的每个码位：
      - 按 em_render 渲染字形
      - 在 gridH 内纵向居中墨迹
      - 从第 0 列裁切到 face_width
      - 量化为四级
      - 把步距及之后的每一列置零
      - 输出 advance、打包后的位图、terminator
6.  重写文件头的 0x0a、0x0b、0x0c、0x14、0x18、0x24、0x28、0x2c、0x38、0x3c。
    其余字段从骨架复制。
7.  依次拼接文件头、区间表、tail 表、补零、字形记录。
8.  断言文件长度等于 data_start + G * P。
```

第 6 步是布局与骨架唯一发生交互的地方。未列出的字段必须保持骨架原值。

## 11. 一致性

满足以下全部条件的文件为合规文件。

1. 第 0 到 3 字节为 `XTF0`。
2. `0x07` 等于 2。
3. `0x14` 等于 `0x38` 之前的 16 字节行数。
4. `0x18` 等于区间表中 `Σ count` 的结果。
5. `cum_index` 为累加值，且最后一个区间的末尾落在 `0x18`。
6. 每行的 `count_x16` 等于 `count << 16`。
7. `0x28 == 2 + 0x0b × stride`，其中 `stride = ceil(0x0a × 2 / 8)`。
8. `0x2c == 0x18 × 0x28`。
9. `0x24 == (0x40 + 16 × 0x14 + 0x3c + 0x1FF) & ~0x1FF`。
10. `0x38` 之后存在 `0x3c` 个字节，且全部落在 8 到 34 之间。
11. 文件长度等于 `0x24 + 0x2c`。
12. 每条记录的 terminator 均为 `0x00`。
13. 第 `0x0a - 1` 列及其之后的像素全部为零。
