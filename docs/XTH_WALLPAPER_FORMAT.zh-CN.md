# XTH 壁纸容器格式规范

版本 1.0 · 适用对象：XTEINK X3 固件 V6.4.x 读取的 `.xth` 文件

[English](XTH_WALLPAPER_FORMAT.md) | **简体中文**

---

## 1. 范围

本文规定 `.xth` 壁纸容器的二进制布局。这是一个 2 bit 灰阶的全屏图像格式，供 XTEINK X3 电子阅读器使用。

`.xth` 文件以明文形式从 SD 卡读取，不加密，也不绑定设备密钥。另有一种容器 `.xtge` 与设备绑定，不在本文范围内。

---

## 2. 约定

- 所有多字节整数均为**小端序**。
- `u16`、`u32` 分别表示无符号 16 位与 32 位整数。
- 偏移量均以文件起始位置为基准，单位为字节。
- 关键词“必须”“不得”“应该”“可以”按 RFC 2119 的用法理解。
- “面板”指目标设备的 528 × 792、四级灰阶显示屏。

---

## 3. 文件布局

```
偏移        长度        内容
0x00        22          文件头
0x16        52272       平面 A
0x16+52272  52272       平面 B
```

总长度为 `22 + 2 × (W × H / 8)`。

标准面板下 `528 × 792 / 8 = 52,272`，总长度为 **104,566** 字节。

---

## 4. 文件头

共 22 字节。

| 偏移 | 类型 | 含义 | 约束 |
|---|---|---|---|
| `0x00` | char[4] | 魔数 | 必须为 `XTH\0` |
| `0x04` | u16 | 宽 `W` | 必须为 8 的倍数；标准面板为 528 |
| `0x06` | u16 | 高 `H` | 标准面板为 792 |
| `0x08` | u16 | 保留 | 必须为 0 |
| `0x0a` | u32 | 负载长度 | 必须等于 `2 × W × H / 8` |
| `0x0e` | u32 | 时间戳 | Unix 秒；读者不校验该值 |
| `0x12` | u32 | 保留 | 必须为 0 |

```c
#pragma pack(push, 1)
typedef struct {
    char     magic[4];      /* "XTH\0"          */
    uint16_t width;         /* 528              */
    uint16_t height;        /* 792              */
    uint16_t reserved0;     /* 0                */
    uint32_t payload_size;  /* 2 * W * H / 8    */
    uint32_t timestamp;     /* Unix 秒          */
    uint32_t reserved1;     /* 0                */
} XthHeader;                /* sizeof == 22     */
#pragma pack(pop)
```

`0x08` 是 `uint16`，不是 `uint32`。按 32 位读取会得到 24 字节的文件头，其后每个字段都会错位。

---

## 5. 像素平面

负载是两个独立的 1 bit 平面，每个 `W × H / 8` 字节。

### 5.1 平面编码

每个平面是一张位图，一位对应一个像素，位序为高位优先。

有两项变换同时生效，都必须处理：

1. **列主序。** 平面按 `W` 段、每段 `H` 位存储。前 `H` 位构成图像的第 0 列，接下来 `H` 位构成第 1 列，依此类推。
2. **水平镜像。** 存储的图像相对显示结果左右翻转。

因此读取一个平面需要解包、按 `(W, H)` 重排、转置、再水平翻转：

```python
bits   = np.unpackbits(np.frombuffer(plane_bytes, dtype=np.uint8))
pixels = bits.reshape(W, H).T[:, ::-1]          # 形状 (H, W)，取值 0/1
```

写入是其逆运算：

```python
plane_bytes = np.packbits(pixels[:, ::-1].T.ravel().astype(np.uint8)).tobytes()
```

把平面当作行主序读取会得到重复平铺且撕裂的图像。镜像不是编码器产生的偏差，它是面板的扫描顺序。

### 5.2 等级合成

平面 A 存放低位，平面 B 存放高位：

```
level = (B << 1) | A
```

| A | B | 等级 | 观感 |
|---|---|---|---|
| 0 | 0 | 0 | 纸白 |
| 1 | 0 | 1 | 浅灰 |
| 0 | 1 | 2 | 深灰 |
| 1 | 1 | 3 | 墨黑 |

面板实测反射率：等级 0 为 1.000，等级 1 为 0.578，等级 2 为 0.132，等级 3 为 0.000。等级 2 的亮度只有纸白的 13%，所以交替使用等级 0 与等级 3 的抖动图案读起来是中间调，等级 1 与等级 2 则要少用。

---

## 6. 色调映射

文件存的是**墨量**，不是**亮度**。这里有两套互为补数的刻度，容易混淆：

```
亮度  q   ：0 为黑，3 为白
墨量      = 3 - q
```

源图中为黑的像素必须落到 `等级 3`。直接写入 q 会得到反相图像：黑的渲染成纸白，白的渲染成墨黑。

写入方把 8 bit 灰度压到四级，可选择是否抖动。在同一台目标设备、同一张测试图上的实测结果：

| 方式 | 真机表现 | 建议 |
|---|---|---|
| Floyd-Steinberg 误差扩散 | 过渡细腻，16 级阶梯能分辨出 16 档 | 应该采用 |
| 8×8 有序 Bayer | 几乎没有过渡感 | 不推荐 |
| 不抖动 | 只剩四个硬色块 | 仅适用于线稿与图表 |

优先采用误差扩散的理由是它把量化误差分散开，让局部网点密度承载中间调；有序抖动产生的是固定图案，而面板有限的反射率范围无法把它还原成过渡。

---

## 7. 构造流程

```
1.  把源图读为 8 bit 灰度，alpha 通道合成到白色背景上。
2.  缩放并定位到恰好 W × H。
3.  压到四级亮度。默认使用蛇形扫描的 Floyd-Steinberg。
4.  把亮度换算为墨量：ink = 3 - q
5.  拆分为两个平面：A = ink & 1，B = (ink >> 1) & 1
6.  按列主序、水平镜像、高位优先打包两个平面。
7.  输出 22 字节文件头，随后依次是平面 A、平面 B。
8.  断言总长度等于 22 + 2 × (W × H / 8)。
```

第 3 到第 6 步的顺序敏感。在换算之后才抖动，或在镜像之前打包，产出的文件能通过结构检查，但解码出来的图像是错的。

---

## 8. 一致性

满足以下全部条件的文件为合规文件。

1. 第 0 到 3 字节为 `XTH\0`。
2. `0x08` 与 `0x12` 为零。
3. `0x04` 处的 `W` 为 8 的倍数。
4. `0x0a` 等于 `2 × W × H / 8`。
5. 文件长度等于 `22 + 0x0a`。

## 附录 B · 解码参考

```python
import struct
import numpy as np

def read_xth(path):
    raw = open(path, "rb").read()
    assert raw[:4] == b"XTH\0"
    w, h, r0 = struct.unpack_from("<HHH", raw, 4)
    size, ts, r1 = struct.unpack_from("<III", raw, 0x0a)
    assert r0 == 0 and r1 == 0
    assert size == 2 * w * h // 8
    assert len(raw) == 22 + size

    def plane(buf):
        bits = np.unpackbits(np.frombuffer(buf, np.uint8))
        return bits.reshape(w, h).T[:, ::-1]

    p = w * h // 8
    a = plane(raw[22:22 + p])
    b = plane(raw[22 + p:22 + 2 * p])
    return w, h, ts, (b.astype(np.uint8) << 1) | a
```
